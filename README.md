# RBLX Презентации — конструктор слайдов

Сайт-презентация с конструктором в стиле Canva. День 1.

## Что умеет

- **2 стартовых слайда**: «Регистрация в Roblox» и «Roblox Studio»
- **Редактирование текста**: двойной клик по тексту прямо на слайде, плюс панель свойств (шрифт, размер, цвет, жирный, курсив, подчёркивание, выравнивание, прозрачность)
- **2 стиля оформления**: ⚡ Неон и ◈ Жидкое стекло (эстетика iOS: blur, скругления, светлые градиенты) — палитра текста автоматически адаптируется под тему
- **Фотографии**: загрузка с диска, перетаскивание файлов на слайд, замена, скругление, изменение ширины
- **✨ Удаление фона** — алгоритм flood-fill от краёв снимка с настройкой чувствительности и сглаживанием краёв (без внешних API, всё локально в браузере)
- **Конструктор как в Canva**: перетаскивание элементов, ресайз за угол, дублирование, слои (вперёд/назад), блоки-подложки
- **Слайды**: добавление, дублирование, удаление, миниатюры, фоны-градиенты на выбор
- **Режим презентации** (кнопка ▶ или F5): стрелки/пробел для навигации, Esc — выход
- **✏️ Редактирование прямо в презентации**: кнопка ✏️ в панели управления — выбор элементов, перетаскивание, двойной клик по тексту, удаление/дублирование, панель свойств и добавление фото работают поверх слайда; слайд автоматически вписывается между панелями
- **Экспорт / импорт проекта** в JSON, автосохранение в localStorage

## Структура

```
index.html        — разметка приложения
css/style.css     — обе темы (неон / жидкое стекло)
js/state.js       — данные: project → slides[] → elements[] (схема v2), фабрики, миграция v1
js/storage.js     — автосохранение localStorage (rblx-pres-v2, миграция из rblx-pres-v1)
js/render.js      — отрисовка: сцена, миниатюры, презентация, тулбар, тосты
js/editor.js      — редактирование: выбор, правка, drag/resize, CRUD, свойства, темы, презентация, удаление фона
js/export.js      — экспорт / импорт / сброс проекта (JSON)
js/app.js         — точка входа: загрузка → тема → отрисовка → инициализация
assets/img/       — иллюстрации для демо-слайдов
```

## Данные (схема v2)

```json
{
  "version": 2,
  "theme": "neon",
  "slides": [
    {
      "id": "…", "bg": "",
      "elements": [
        { "id": "…", "type": "text|image|block",
          "x": 60, "y": 46, "w": 720, "h": 78,
          "rotation": 0, "zIndex": 0,
          "props": { "text": "…", "fontSize": 58, "…": "…" } }
      ]
    }
  ]
}
```

Геометрия (`x, y, w, h, rotation, zIndex`) — на уровне элемента, всё содержимое — в `props`.
Старые сохранения (rblx-pres-v1, плоские элементы) мигрируют автоматически при загрузке.

```js
## Автосохранение и история

- **Автосохранение** — `js/storage.js`: запись в `localStorage` (ключ `rblx-pres-v2`)
  с debounce 350 мс после каждого `setState()`; немедленный `saveNow()` на
  `beforeunload`/`pagehide` и при скрытии вкладки. Загрузка — при старте (`load()`);
  после загрузки история обнуляется (`resetHistory()`).
- **Undo/Redo** — стеки снимков **вне** `state` (`js/state.js`):
  `past`/`future`, лимит 50, `historyLock` (не пишет запись во время самого
  restore). Снимок — весь слайд-проект (`p`) + текущий слайд (`c`).
  Каждый живой жест (drag, ресайз, правка текста, смена свойств) коммитится
  **одной** записью, потому что `setState()` сравнивает до-состояние с
  `lastCommitted` (до-жестовым), а не снимком в момент вызова.
- Навигация по слайдам — не история (не пишет и не чистит `redo`).
- Клавиатура (`js/editor.js`): **Ctrl+Z** — undo, **Ctrl+Y** и **Ctrl+Shift+Z**
  — redo; внутри полей ввода работает нативный undo (Ctrl+Z там не перехватывается).
- Узлы элементов привязаны к модели **по id**, а не по ссылке: после undo/redo
  project заменяется новыми объектами и обработчики резолвят элемент заново.
- **Ручки выделения**: 8 точек ресайза (`nw n ne e se s sw w`) + ручка поворота
  сверху на «стебле». Текст меняет только ширину (n/s спрятаны — высота от
  содержимого), картинка сохраняет пропорции (`props.ar`), блок ресайзится
  свободно. Каждый жест коммитится одной записью истории.
- **Множественное выделение**: Shift+клик (добавить/убрать), рамка мышью от
  фона (тест пересечения в координатах слайда, Shift+рамка — объединение).
  `state.ui.selectedIds[]` + `selected` = основной; drag двигает всю группу;
  undo/redo сохраняет выделение, если объекты живы.
- **Буфер**: внутренний clipboard, Ctrl+C / Ctrl+V / Ctrl+D (в полях ввода —
  нативные); вставка — копии со сдвигом +16 и новыми id, одна запись
  истории; Delete/Backspace — на всё выделение.
- **Слои**: `layerSel(up|down)` — на всё выделение одной записью (тулбар ⤒/⤓);
  Del/Backspace — на выделение, **заблокированные не удаляются**.
- **Привязка (snap)**: во время drag — центр слайда, края слайда, рёбра и
  центры других элементов (радиус 6 экранных px); совпадение рисует
  розовую направляющую `.guide` (вертикаль/горизонталь), снимается на
  отпускание.
- **Блокировка 🔒** (`props.locked`): тулбар переключает на всём выделении;
  заблокированный — выделяется кликом, но не двигается/не ресайзится/не
  поворачивается/не удаляется (ручки скрыты).
- **Группировка Ctrl+G / Ctrl+Shift+G** (`props.groupId`): клик по члену
  выделяет группу целиком, drag двигает всю группу.
- **Редактирование текста двойным кликом** (15): dblclick → `startEdit(id)`
  (только `type: text`, заблокированные не правятся) → `editingId`,
  contenteditable, тулбар/ручки скрыты; клик по другому элементу, blur,
  Escape — выход с коммитом (одна запись истории на правку). Во время правки
  стрелки/Del не утекают в глобальные шорткаты, нативное выделение браузера
  не трогаем (Enter/Shift+Enter работают как в contenteditable). Blur-обработчик
  привязан к **сессии** (`editSeq`): `focus()` шлёт blur на прежнем активном
  узле, а в презентации и на слайде у элемента один и тот же model id — без
  счётчика сессии такой «чужой» blur закоммитил бы новую правку.

```

Любое изменение состояния проходит только через `setState()` (см. `js/state.js`).
Перерисовка обновляет узлы сцены/презентации на месте, если структура слайда не
изменилась — поэтому рендер безопасен во время кликов и жестов. Исключение —
«живой предпросмотр» внутри жеста (перетаскивание, слайдеры, ввод текста): он
пишет прямо в узел и модель, а коммит жеста идёт через `setState()`.
